# Senior Expert QA

**Owns:** the release gate. Runs last on every task. Nothing is delivered without a QA result.

## Rules

- Report only what was actually checked. A check that could not be run is listed under `Unverified`, never marked as passed.
- Run only the sections relevant to the change, plus **Always** and **Regression**.
- On FAIL: name the item, the cause, and the fix. The owning role fixes it, then QA re-runs the failed items.

## Always

- [ ] `npm run build` succeeds.
- [ ] `npm run lint` passes with no new warnings.
- [ ] `npx tsc --noEmit` passes.
- [ ] No hydration warnings or console errors on affected pages.
- [ ] Grounding rules in `SKILL.md` followed: no invented files, APIs, env vars, or business data.

## UI changes

- [ ] Matches `context/design-system.md`; no anti-generic patterns; locked decisions unchanged.
- [ ] Layout correct at 360 / 768 / 1024 / 1440px; no horizontal scroll.
- [ ] Loading, empty, and error states render correctly (test with empty tables and a failing Google API).
- [ ] Keyboard-only navigation works; focus visible; menu/modal focus trap and Escape work.
- [ ] Contrast AA on all text, including reduced-opacity secondary text.
- [ ] Reduced-motion setting disables non-essential animation.

## Data and business rules

- [ ] No hardcoded business info anywhere in components (search for phone patterns, address, prices, rating numbers).
- [ ] Rating shows live/cached Google value, or is hidden — never a fixed number.
- [ ] CMS edit updates the public page after save (cache revalidation works).

## Auth and access

Test each as: guest, customer A, customer B, admin.

- [ ] Guest cannot reach customer or admin pages or actions.
- [ ] Customer cannot reach `/admin` or call any admin action directly.
- [ ] Customer A cannot read or modify customer B's orders, appointments, profile, or chat by changing an ID.
- [ ] Logout invalidates the session.

## Forms and input

- [ ] Valid input succeeds.
- [ ] Invalid, empty, oversized, and special-character input (including `<script>`, quotes, emoji, SQL fragments) is rejected or safely stored and rendered as text.
- [ ] Rate limits trigger on repeated submissions.

## Feature-specific

- **Appointments:** concurrent booking of the same slot results in exactly one success; times display in Asia/Manila; booking outside business hours is rejected.
- **Shop:** client-modified price/quantity is ignored; stock never goes negative under concurrent orders; order items keep the purchase-time price.
- **Chat:** customer sees only their own thread; admin sees all; messages persist after refresh; reconnect recovers missed messages; length limit enforced.
- **Uploads:** non-image and renamed files rejected; oversized files rejected.

## Release checks (before deploy)

- [ ] Lighthouse mobile on `/`: Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 95.
- [ ] Security headers present (check response headers on a public page).
- [ ] `npm audit`: no High/Critical in production dependencies.
- [ ] `.env.example` matches the env variables the code reads.

## Regression

- [ ] `/`, `/about`, `/services`, `/accessories`, `/contacts` render without errors.
- [ ] Sticky navbar and NAP + Maps section before the footer still work.

## Output

```
Checked: <sections run>
Failed: <item — cause — fix> (only if FAIL)
Unverified: <checks not run and why>
```
